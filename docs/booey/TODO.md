# Krystal.Booey TODO

Open work outside the WebKit port's current slice. Port-specific detail (verdicts, differences, FIXMEs per file) stays in `PORTING.md`; this is the short list; the order in which the big items are tackled is `ROADMAP.md`. Paths are relative to `Krystal.Booey/`.

## Infrastructure

- **Event loop and rendering loop** — timers run on the host's time and the style recalc and layout timers schedule style and layout (G6a); `Page` runs the "update the rendering" steps once a frame (G6b); mutation observers and `slotchange` are delivered at microtask checkpoints (G6c). Idle callbacks and script timers wait for scripting (*G6 plan* in `docs/gfx/DESIGN.md`). https://html.spec.whatwg.org/#event-loops
- **Settings** — `Page/Settings.hpp` holds the experimental and embedder flags and the font size values; the other values upstream reads from `Settings` (`textAreasAreResizable`, `hiddenUntilFoundEnabled`, `coreMathMLEnabled`, ...) are upstream's defaults in code. The media text track display quirk is never set (no document quirks).
- **Resource loading** — images (G7b), style sheets (G8a) and `@font-face` sources (G8b) load, through the host's `LoaderStrategy`; sheets decode as UTF-8 only, and there are no preloads, icons or manifests (`src/HTML/HTMLLinkElement.cpp`). https://html.spec.whatwg.org/#link-type-stylesheet
- **Fonts** — the host registers fonts (`Graphics/FontDatabase.hpp`) and sets generic families in `Settings`; web fonts load from `@font-face` (G8b), but there's no `FontFace`/`FontFaceSet` (`document.fonts`), SVG fonts, font collections, or features, palettes and variations applied to fonts (`CSS/Font/`, `Graphics/FontCustomPlatformData.hpp`); text is measured and shaped, but not drawn. https://drafts.csswg.org/css-font-loading/
- **Painting** — pages paint into display lists that Krystal.UI replays, and hit test (G4, `docs/gfx/DESIGN.md`); CSS images and `<img>` load, paint and animate (G7b to G7d; no broken image icon), `filter` paints through Render2D's layer filters (G11a; no software filters, so uneven blurs, `luminanceToAlpha` and `filter: url()` paint unfiltered), `backdrop-filter` is drawn on composited layers (G11b; not by a page that doesn't composite), masks (`mask-image` layers and `mask-border`) are drawn, composited or not (G11c; no `mask-image: url()` to SVG `<mask>`), and selection and carets, SVG and form controls aren't drawn (FIXMEs; *G4 plan*, *G11 plan*). Pages composite (G12b): layers that need it (filters, 3D transforms, overlapping a composited layer, and the rest of upstream's reasons) get backings of their own, which Krystal.UI's layer tree draws, and changes repaint only what they damage in the backing they hit. Scrolling the view or a box inside the page moves layers and repaints nothing but the scrollbars (G12d): boxes that scroll their overflow and fixed elements composite, and sticky boxes stick (G12e; they composite inside boxes that scroll on layers, and repaint when stuck to the view); there's no async scrolling: scrolls run on the main thread. Changes of a composited layer's transform, opacity or filter recomposite it without repainting, and transform and opacity animations run on layers (G12c); other animations restyle the page each frame.
- **Frames** — `LocalFrame` has a loader that navigates within its document (B2a) loads and unloads documents with their events and a navigation scheduler (B3b), keeps a session history (B3c) and a back/forward cache (B3d), and the History and Navigation APIs (B3e), but no frame tree (no iframes), scripting or printing; its document has a window with the spec's `Window` interface (B3a); `LocalFrameView` scrolls, with scrollbars (G5a, G5b), and its visual viewport is its layout viewport (no pinch zoom) (`Page/LocalFrame.hpp`, `Page/LocalFrameView.hpp`).
- **Logging** — no channel for exceptions thrown by event listeners or for parse errors (`src/DOM/Algorithms/EventDispatcher.cpp`, `src/HTML/Parser/HTMLTreeBuilder.cpp`).
- **Inspector** — a debugging tool for pages (later): the DOM tree, matched rules and computed style, box model and layout overlays, editing styles live, event listeners. Upstream's inspector (`inspector/`) talks to a JavaScript front end over a protocol; ours could be a Krystal.UI panel over the same agents (DOM, CSS, layer tree) instead. Its hooks were dropped as `wont` while porting and come back with it: the CSS parser's observer (source ranges), the resolver's CSSOM wrappers, forced pseudo-classes (`:visited`, `:hover`) and the instrumentation points (`PORTING.md`).

## Style

- **Input events** — mouse, keyboard and focus events, clicks, hover and active state and cursors are done (G4f to G4h, `docs/gfx/DESIGN.md`); wheel events and keyboard scrolling are done too (G5b); positions in the DOM and where they render, text iteration and visible units are done (G13a), and so is selecting with the mouse, with the selection painted (G13b), and with the keyboard, with the DOM's `Selection` and copying (G13c); and so are carets in editable content (G13d), and typing, deleting, line and paragraph breaks, undo, and cutting and pasting plain text in it (G14a); rich editing commands (`execCommand`'s formatting, lists, indenting, links), pasting HTML, spelling, input methods, pointer and touch events, smooth and momentum scrolling, drag and drop (drags within a page and their images are done, B10c and B10d; drags in from other applications aren't), context menus, access keys and text input aren't (`src/Page/EventHandler.cpp`). https://w3c.github.io/uievents/
- **Focus navigation** — Tab order is done (G4h2); spatial navigation, popovers as focus navigation scopes and frames aren't (`src/HTML/Algorithms/FocusAlgorithms.cpp`). https://html.spec.whatwg.org/#sequential-focus-navigation
- **Animations and transitions** — CSS transitions and animations run on the rendering update (G9); the Web Animations interfaces, scroll and view timelines (named timelines, `scroll()`, `view()`, animation ranges), accelerated animations and frame rates wait (`PORTING.md`, *Open*).
- **Other pseudo-classes** — `:target`, `:autofill`, `:state()`, `:popover-open`, `:modal`, `:fullscreen`, media playback states and view transitions return false (`src/CSS/Selectors/SelectorChecker.cpp`).
- **Forms** — owners, validity, submission to the host and the input types' behaviour are done (G14b); the tree builder doesn't give controls the parser's form element pointer (`SetFormSetByParser`) or reset them, the validation message bubble, files, other encodings, dialogs (`method=dialog`) and autofill aren't (`src/HTML/Parser/HTMLTreeBuilder.cpp`, `PORTING.md` *Forms*). Text fields are done (G14c), without autofill, datalists' suggestions, the caps lock indicator or recent searches; the theme (Adwaita), buttons, painted checkboxes and radios and the spin button are done (G14d1), and so are ranges, progress and meters (G14d2), `<select>` (G14d3), and dates and colours (G14d4). Colour inputs don't support `alpha` or `colorspace`; the date picker's day names and first day of the week aren't localised; number fields don't localise their values (`localizeValue`); there's no user activation, so pickers and `showPicker()` don't check for a gesture. Access keys aren't pressed yet (`HTMLElement::AccessKeyAction` is ready). Ranges' tick marks wait for datalists. The theme's search field icons are SVG mask images, which wait for SVG images. https://html.spec.whatwg.org/#forms
- **`user-select`** — only `-webkit-user-select` exists, as upstream has it (`codegen/css-properties.json`); pages writing the standard `user-select` get nothing. Add `user-select` as the property (with a choice between the spec's initial `auto` and upstream's `text`), make `-webkit-user-select` a legacy alias or drop it, and move the user agent sheets to the unprefixed name. https://drafts.csswg.org/css-ui-4/#propdef-user-select
- **Auto directionality** — `dir=auto` and `<bdi>` are always LTR (no bidi data) (`src/CSS/Selectors/SelectorCheckerTestFunctions.cpp`). https://html.spec.whatwg.org/#the-directionality
- **Document language** — no default language from a `Content-Language` pragma or header (`EffectiveLang`). https://html.spec.whatwg.org/#pragma-set-default-language
- **Typed OM** — `styleMap`, `attributeStyleMap`, `computedStyleMap()` and `css/typedom` aren't ported; needs `DOMMatrix` and `ParseTransformRaw` first (`CSS/Properties/Consumers/Transform.hpp`). https://drafts.css-houdini.org/css-typed-om/
- **CSSOM** — async `CSSStyleSheet.replace()` (promises).
- **Layout** — block, inline, flex, grid and table layout are done, and style reads layout (size container queries and container units); the CSSOM View geometry and scrolling APIs are done. Anchor positioning resolves anchors, `anchor()`, `anchor-size()` and `position-area` (B4g1), with position options and `position-visibility` (B4g2) and the anchors' scroll adjustment (B4g3); the viewport scrolls since G5a, with scrollbars, the wheel and the keyboard since G5b (`PORTING.md` *Open*, *The viewport scrolls*).

## DOM

- **Custom elements** — the registry, creation, upgrades and callback reactions (B1a), and `ElementInternals`, form-associated custom elements and `:state()` (B1b) are done (`ROADMAP.md`). Form-associated custom elements' state is restored from the session history (B3c2), but not by autofill; the internals' ARIA members wait for accessibility. Listeners can be added from C++ functions, owned by `EventListenerHandle`s, and Krystal.UI views define custom elements for the pages they load (B1c); the view gives its definitions to each new document through the frame loader client's `DispatchDidClearWindowObject` (B3b1). Failed constructions and upgrades aren't reported (no console). The `[CEReactions]` members Booey doesn't implement yet get their reaction scope when they're ported (`PORTING.md` *Custom elements*). https://html.spec.whatwg.org/#custom-elements
- **Event handler attributes** — no `EventHandler` IDL attributes (`onabort`, `onslotchange`, the global `on*` handlers) (`DOM/AbortSignal.hpp`, `DOM/ShadowRoot.hpp`). https://html.spec.whatwg.org/#event-handler-attributes
- **Event listeners** — awkward to add and remove with lambdas (need a comparable wrapper like `AbortAlgorithmCallback`). https://dom.spec.whatwg.org/#add-an-event-listener
- **`createEvent()`** — always returns a plain `Event` (no event factory), with the interface name as its type and its initialized flag set (it should be unset until `initEvent()`) (`src/DOM/Document.cpp`). https://dom.spec.whatwg.org/#dom-document-createevent
- **Dependent abort signals** — `CreateDependentAbortSignal` keeps its source signals in a vector with messy de-duplication, and the garbage collection rule (keep a dependent signal alive while it has sources and listeners) isn't implemented (`src/DOM/Algorithms/AbortAlgorithms.cpp`). https://dom.spec.whatwg.org/#abortsignal-garbage-collection
- **`NodeFilter`** — works but is clunky to use from C++ (`DOM/NodeIterator.hpp`, `DOM/TreeWalker.hpp`). https://dom.spec.whatwg.org/#interface-nodefilter
- **Slot assignment on insertion** — inserted and moved nodes aren't assigned a slot by the insertion steps' own rules (`TODO(impl): SLOTTABLES` in `src/DOM/Algorithms/MutationAlgorithms.cpp`); `slotchange` is signalled (G6c). https://dom.spec.whatwg.org/#concept-node-insert
- **Document encoding** — not set on creation or passed to clones; `characterSet` is always UTF-8 (`src/DOM/Document.cpp`, `src/DOM/Algorithms/NodeAlgorithms.cpp`). https://dom.spec.whatwg.org/#concept-document-encoding
- **Memory** — documents are freed when their last reference and node go (M1, `PORTING.md`, *Freeing documents*); event listener callbacks that hold their own target keep it alive (no garbage collector).
- **ID lookups** — `getElementById` and the selector ID fast paths walk the tree (no ID map per tree scope) (`DOM/Mixins/NonElementParentNode.hpp`, `src/DOM/SelectorQuery.cpp`).
- **Live collections** — `LiveNodeList`/`LiveHTMLCollection` re-walk the tree on every access (no caching) (`DOM/Internals/`).
- **Public tree accessors** — `FirstChild()`, `ParentNode()` and friends return raw pointers; the public API should return `RefPtr`. https://dom.spec.whatwg.org/#interface-node
- **Token lists** — only `classList` follows its attribute; `relList`, `sandbox`, `sizes`, `blocking`, `htmlFor` should update from `Element::OnAttributeChanged`.
- **Header weight** — `Node.hpp` includes the registered observer and mutation record types; forward declare them if possible.
- **Small fixes** — `NodeAlgorithms::Equals` compares attributes by position; `Node.cpp:212` doesn't use `element1`; `NameValidation.cpp` decodes whole strings and assumes valid UTF-8.

## HTML

- **`outerText`** — the getter and setter are TODOs (`innerText` is done, G14c) (`src/HTML/HTMLElement.cpp`). https://html.spec.whatwg.org/#the-innertext-idl-attribute
- **User agent part names** — the internal parts of the controls' shadow trees keep upstream's `-webkit-` prefix (`-webkit-search-cancel-button`, `-webkit-inner-spin-button`, `-webkit-textfield-decoration-container`, ...; `codegen/css-pseudo-selectors.json`, `codegen/user-agent-style-sheets/html.css`, `useragentpart` values in `src/HTML/`). They parse only in user agent sheets, so pages never see them; renaming them to a `-krystal-` prefix would go with replacing the theme (see *G14 plan* in `docs/gfx/DESIGN.md`).
- **`HTMLElement` API** — `click()`, `accessKeyLabel`, `draggable`/`spellcheck` defaults, `writingSuggestions`, `autocapitalize`, `autocorrect`, `attachInternals()`, removal and move steps (`src/HTML/HTMLElement.cpp`, `HTML/HTMLElement.hpp`).
- **`dataset`** — no `DOMStringMap` for `data-*` attributes. https://html.spec.whatwg.org/#dom-dataset
- **`title` advisory information** — the "get advisory information" algorithm. https://html.spec.whatwg.org/#the-title-attribute
- **`document.lastModified`** — not implemented. https://html.spec.whatwg.org/#dom-document-lastmodified
- **Document collections** — `images`, `embeds`, `plugins`, `links`, `forms`, `scripts`, `getElementsByName()`; `HTMLAllCollection`, `HTMLFormControlsCollection`, `HTMLOptionsCollection` (`src/DOM/Document.cpp`). https://html.spec.whatwg.org/#dom-tree-accessors
- **Microsyntaxes** — lists of floating-point numbers, lists of dimensions, dates and times (`HTML/MicroParsers/`). https://html.spec.whatwg.org/#common-microsyntaxes
- **Enumerated attributes** — several IDL attributes aren't limited to known values (`crossOrigin`, `referrerPolicy`, `decoding`, `loading`, `fetchPriority`, `as`, `<ol type>`) (`src/HTML/HTMLImageElement.cpp`, `HTMLLinkElement.cpp`, `HTMLAnchorElement.cpp`, `HTMLMetaElement.cpp`, `HTMLOListElement.cpp`).
- **`ElementInternals` reflection** — reflected attributes on `ElementInternals` (`HTML/Attributes/Reflection.hpp`). https://html.spec.whatwg.org/#reflecting-content-attributes-in-idl-attributes
- **Forms** — form owners, the form API on controls (`form`, `labels`, validity, selection, `valueAsNumber`/`valueAsDate`, `stepUp()`), `<select>`/`<option>` APIs, `<label>` control, submission (`SubmitEvent`, `FormDataEvent`) (`HTML/HTMLInputElement.hpp`, `HTMLSelectElement.hpp`, `HTMLFormElement.hpp` and the other control headers). https://html.spec.whatwg.org/#forms
- **Tables** — `caption`/`tHead`/`tBodies`/`rows` and the row, section and cell APIs (`HTML/HTMLTable*Element.hpp`). https://html.spec.whatwg.org/#the-table-element
- **Lists** — `<ol>` starting value and `<li>` ordinal value. https://html.spec.whatwg.org/#ordinal-value
- **`<meta http-equiv>`** — `refresh`, `content-language` and `default-style` are done (B3b4); `Content-Security-Policy` and the other security pragmas wait for a security policy. https://html.spec.whatwg.org/#pragma-directives
- **`<link>`** — explicitly enabled flag on `disabled` changes, `LinkStyle` loading (`src/HTML/HTMLLinkElement.cpp`). https://html.spec.whatwg.org/#the-link-element
- **`<template>`** — constructor and parser steps aren't spec compliant (`src/HTML/HTMLTemplateElement.cpp`, `src/HTML/Parser/HTMLTreeBuilder.cpp`). https://html.spec.whatwg.org/#the-template-element
- **Render blocking** — unblock rendering when a render-blocking element disconnects or stops being render-blocking (`src/HTML/Algorithms/RenderBlocking.cpp`). https://html.spec.whatwg.org/#render-blocking-mechanism
- **Document readiness** — `about:srcdoc` (`src/DOM/Algorithms/DocumentAlgorithms.cpp`); loaded documents go through it with their load timing (B3b2). https://html.spec.whatwg.org/#current-document-readiness
- **Interactive elements** — the top layer (B4a), close watchers (B4b), `<dialog>` (B4c), popovers (B4d), `<details>` (B4e), commands (B4f), anchors with `anchor()`, `anchor-size()` and `position-area` (B4g1), position options and `position-visibility` (B4g2), the anchors' scroll adjustment (B4g3) and the editor sample (B4h) are done; revealing `<details>` and `hidden=until-found` content for find in page waits for find (`ROADMAP.md`). https://html.spec.whatwg.org/#interactive-elements
- **Hyperlinks** — B2 (`ROADMAP.md`): links, the hyperlink utilities and the loader (B2a), fragments, `:target` and `hashchange` (B2b), text fragments with the custom highlights' model (B2c), image maps (B2d) and the editor sample (B2e) are done. Text directives match ignoring ASCII case only (no `findPlainText`), and there's no text indicator or directive generator. Pings, the `referrerpolicy` attribute and sanitised `download` names wait for network loads and origins. https://html.spec.whatwg.org/#api-for-hyperlink-elements
- **Embedded content** — image `decode()`, lazy loading, forms and re-selecting sources when media queries change (G7c did the rest of `<img>` and `<picture>`); media, video, track, iframe and object APIs (`src/HTML/HTMLImageElement.cpp`, `HTML/HTMLMediaElement.hpp`). https://html.spec.whatwg.org/#embedded-content
- **`<script>`** — `text` attribute and `HTMLScriptElement.supports()` (`src/HTML/HTMLScriptElement.cpp`).

## Krystal.Core

- `IntrusivePtr` `Downcast`/`DynamicDowncast` can't take an explicit target and `Downcast` rejects null; `DefaultHash<StringAtom>` isn't ported (`PORTING.md`, *Open*).

## Not supported (by choice)

Realms and global objects other than the window (the window exists from B3a1, and a listener's global is its target's window), origins and `document.domain`, ancestor origins, service workers, trusted types, Content Security Policy and `nonce`, policy-controlled features, the JavaScript-only parts of the specs (`handleEvent`, IDL callbacks, HTML element constructors), scripting in the parser. Constructors that need a global object (`Document()`, `DocumentFragment()`) take a document instead. These are marked `SPEC-VIOLATION` at the call sites.
