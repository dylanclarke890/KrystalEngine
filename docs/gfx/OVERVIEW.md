# Graphics

Graphics is three layers. Krystal.Gfx holds the render hardware interface (the RHI, `krys::gfx`) and Render2D, an immediate-mode 2D renderer built on it; neither knows anything about Booey. Krystal.UI is the only module that knows both Booey and Gfx: it hosts Booey pages (`ui::View`), replays Booey's display lists through Render2D, and supplies the strategies and providers Booey asks its host for. Krystal.PAL supplies windows, input types, clipboard, cursor, drag and drop, and gamepads. Krystal.Core supplies colour types and `CommandList`; Krystal.Text supplies font files and faces. Krystal.Booey never depends on Krystal.Gfx.

## The RHI

- **Shape.** A modern-API style with explicit ownership: whoever creates a resource destroys it, creation returns `Expected` (shader and pipeline errors carry the compile or link log prefixed with the debug name), and nothing throws. Resources are generational `Handle<TTag>` values (24-bit index, 8-bit generation, 0 invalid) in a `Pool`; stale handles resolve to null (an assert in debug builds, a no-op in release). Handle types are buffer, texture, sampler, shader, pipeline and swapchain. The device logs every resource still alive at destruction.
- **Device.** `Device` is virtual and chosen at run time; OpenGL (`krys::gfx::opengl`, in the `OpenGL/` subdirectory) is the only backend. Device creation needs no window: the OpenGL context lives on a hidden window the device owns and each swapchain attaches a real window to it, so several windows share one device and tests render offscreen. Equal sampler descriptions return the same handle (reference counted by `Destroy`). Also on `Device`: `ReadTexture` (synchronous readback that waits for the GPU), `GetTextureDesc`, `SetVSync`, `WaitIdle` and `Limits`.
- **Pipelines** are immutable (shaders, vertex layouts, topology, raster, depth-stencil and blend state, output formats, resource layout) and created up front. Dynamic state is viewport, scissor, bound buffers and textures, blend constant and stencil reference. Shaders are GLSL 4.50 strings passed to the driver unchanged (they must start with `#version`), with numbered `layout(binding = N, std140)` slots and no uniform-name lookups; the C++ mirrors of the blocks are `static_assert`-checked. GLSL puts all uniform block members in one namespace, so blocks can't share member names. Pipelines keep their own compiled stages, so shaders can be destroyed after pipelines are created. Per-draw data goes in an ordinary uniform block from `AllocateTransient`; there are no push constants.
- **Render passes** bracket drawing into explicit targets with `Load`/`Clear`/`DontCare` and `Store`/`DontCare`. Buffer bindings carry over between passes; each pass binds its own pipeline. There is no implicit "whatever was bound last" target.
- **Command buffers** record plain structs into Krystal.Core's `CommandList` (no virtual call per draw); `Device::Submit` replays and resets. Debug builds assert on misuse where it happens (drawing outside a pass or without a pipeline, nested passes, copies inside a pass, unbalanced debug groups). Destroying a resource that is recorded but not yet submitted is an error.
- **Frames.** `BeginFrame`, record, `Submit`, `Present`, `EndFrame`. `AllocateTransient` hands out per-frame memory from one persistently mapped buffer split into `FramesInFlight` (3) regions; `BeginFrame` waits on the fence of the region it reuses, and an exhausted frame returns an empty allocation (an assert in debug builds). `FrameNumber()` counts frames begun, so caches know when a frame's commands have been submitted; the atlases, pooled textures and the layer pool rely on it.
- **Conventions.** Pixel coordinates (viewports, scissors, texture regions) have a top-left origin with y down; texture memory starts with the top row and UV (0, 0) is the top-left texel; clip space has y up and depth 0 to 1. Rendering into a texture and sampling it doesn't flip the image. The RHI has no colour type: clear values are four numbers in the target's encoding. `BlendMode` and `GradientSpreadMethod` live in Krystal.Core (`Colour/`) and are shared by Booey and Render2D.
- **OpenGL 4.5 backend** (`GLDevice`, `GLContext`, `GLMappings`). The WGL context is created by loading entry points through a throwaway legacy context, then making a 4.5 core context (a debug one when validating). Buffers are `glNamedBufferStorage` with `GL_DYNAMIC_STORAGE_BIT`; textures use `glTextureStorage*` (BGRA is stored as RGBA and uploaded as `GL_BGRA`). A pipeline is a linked program plus a vertex array built from its layouts, with a cache of the last applied blend, depth-stencil and raster state so binding changes only what differs. Render passes use a cached framebuffer per attachment set (framebuffer 0 for a swapchain) and `glInvalidateNamedFramebufferData` for discards. `glClipControl` is `GL_UPPER_LEFT` for textures and `GL_LOWER_LEFT` for windows, with the front face flipped to match. `GL_FRAMEBUFFER_SRGB` follows the target format. Clears open the write masks and scissor first. Debug output goes to the global logger.
- `OpenGL/ShaderReflector.hpp` exists but nothing uses it. Shaders are GLSL strings embedded in `Renderer2D.cpp` and `FilterRenderer2D.cpp`.

## Render2D

Render2D (`Krystal.Gfx/Render2D/`, namespace `krys::gfx`) is a 2D renderer whose API mirrors upstream's `GraphicsContext` primitives rather than CSS, so Booey's painters express everything as these calls. Game HUD or debug overlay code can use it directly.

**API.**
- `Renderer2D::Begin(commands, Render2DTarget)` and `End()`. A `Render2DTarget` is a swapchain or a texture (unorm format, optional clear colour); the default format is `RGBA8Unorm`. `GetCommandBuffer()` and `GetDevice()` let a frame record other renderers' passes into the same command buffer first, so a frame can draw textures other renderers rendered into during the frame; each such renderer records at its own `End`, before the passes that draw the texture.
- Stacked state: `Save`/`Restore`, transform, clip, blend mode, composite operator, drop shadow.
- Clips: `ClipRect`, `ClipRoundedRect`, `ClipOut*`, `ClipPath`, `ClipOutPath`, plus `GetClip`/`SetClip`.
- Fills and strokes: `FillRect`, `FillRoundedRect`, `FillRectWithRoundedHole`, `FillPath`, `StrokePath`, `StrokeLine`. Also `DrawImage`, `DrawGlyphs`, and `BeginLayer`/`EndLayer`.
- `Paint2D` is a solid colour, a gradient (linear, radial as a two-point conical model, conic; stops flattened on the CPU) or an `ImagePattern2D`. A pattern is a texture repeated in pattern space (its transform into the draw's coordinates, tile size, spacing after each tile), sampled linearly or nearest, faded by an opacity, repeating or clamped along each axis. Patterns have a uniform block and texture unit of their own per batch, so they paint rects, rounded rects, paths, strokes and glyphs alike. Without spacing the texture is sampled continuously with a repeating sampler so tiles join without seams.
- Colours are sRGB straight alpha in the API and premultiplied in the shader. Blending is on encoded (non-linear) values everywhere, as browsers blend; a target in an sRGB format asserts. Textures in sRGB formats are decoded by the GPU when sampled and re-encoded by the shader, so premultiplied images belong in unorm formats. A 3D renderer sharing a window must write encoded values itself.

**Recording and replay.** Draws are not executed when made. Each is appended as a 20-to-112-byte instance record (rect, radii, hole, colour, UVs, flags, transform), batched in painter's order, and turned into command-buffer passes at `End`. A batch breaks on a change of clip chain, texture or sampler, gradient or pattern, blend mode, or layer. Instances are drawn as 4-vertex strips whose corners come from `gl_VertexID`, and each carries its own transform, so draws under different transforms stay in one draw call. Pipelines are created on first use per target format (with a `PlusLighter` variant and blur and composite-operator variants) and cached. `GetStats()` reports the last frame's instances, batches, mask and glyph cache hits and backdrop copies.

**Two ways a shape reaches the screen, both on the GPU.**
- Analytic shapes: rects, rounded rects with circular corners, rects with a rounded hole, straight strokes (`StrokeLine`: each dash a rect, round dots circles) and their blurred shadows. The shader computes coverage from the signed distance to the shape, with an antialiasing width that follows the transform.
- Coverage masks: paths, general strokes (the CPU `PathStroker` makes the outline, dashing first, filled non-zero), elliptical corners and big glyph outlines. `PathRasteriser` rasterises them on the CPU (16 sub-scanlines per row) into 8-bit masks cached in the `MaskAtlas` (R8 pages packed in shelves). The key is path, fill rule, the transform's linear part and the fractional translation, so whole-pixel moves reuse a mask. Masks over `MaxPackedSize` get their own texture, and masks unused for a few frames are evicted. A mask is drawn as an untransformed, pixel-aligned quad whose colour is multiplied by the mask's coverage.

**Atlases.** The glyph atlas (R8 pages for coverage, RGBA pages for colour glyphs; `FontFace2D::HasColour` marks colour fonts) and the mask atlas are separate, because glyphs are small and long-lived while masks are large and short-lived, but share the shelf-packing helper `AtlasPages`. When every page is full, the least recently used page the current frame hasn't drawn from is cleared; if the frame has drawn from every page, the item gets its own texture, destroyed after a frame without use. Switching between atlases breaks a batch. Glyph instances use the `AlphaMask` flag (bit 7) to read a texture's alpha as coverage, and `GlyphAtlas::GetGlyph` takes a blur for shadows.

**Clips** are antialiased as browsers do: every draw multiplies its coverage by how much of each pixel its clips let through.
- A `ClipRect` on whole pixels under an axis-preserving transform is the scissor alone.
- Other shape clips (rects under any transform, rounded rects, and their clip-outs) are evaluated exactly in the shader, each under its own transform, and nested clips multiply. Each batch binds its clip chain as a uniform block (slot 1; the scissor is the chain's bounds).
- Path clips sample the path's coverage mask (texture unit 1, the white texture when unused). A second nested path clip multiplies all the chain's path clips on the CPU into a per-frame transient mask (`MaskAtlas::UploadTransient`).

**Layers** (`BeginLayer`/`EndLayer`, upstream's transparency layers) serve `opacity`, `mix-blend-mode`, `isolation`, filters and image-buffer clips.
- A layer's draws go to an offscreen texture sized to what was drawn within the clip (rounded up to 64 px). The textures are pooled and reused across frames, not within one, and destroyed after 120 unused frames. The layer composites as one premultiplied image at its opacity, blend mode and composite operator.
- Passes are recorded children first, the target last, each offsetting its viewport and scissor by the layer's position so instances, scissors and clips stay in target pixels. A layer that shows nothing gets no texture or pass. Layer composites keep the parent's scissor but no shape or path clips, because the draws were already clipped.
- `LayerFilter2D` is a colour matrix (applied in the composite's fragment shader on un-premultiplied texels), a Gaussian blur, a drop shadow, or `LuminanceToAlpha` (premultiplied luminance to alpha, as Skia's luma filter). A blur grows the layer by three standard deviations within the clip it began with and blurs in two passes through a scratch texture (`Render2D.Blur`, a Gaussian sampled at every texel up to 256 px out). A drop shadow blurs the layer's alpha into a second texture composited in the shadow's colour and offset before the layer. `EdgeMode2D` (`None`, or `Duplicate`, which reads the nearest edge texel past the clip) is used by backdrop blurs. Blur can only read what is inside the clip, which drives `AbsoluteFilterRepaintRect`.

**Blend modes and compositing operators.**
- All of Compositing and Blending Level 1 mix with what is beneath. A draw with a backdrop-reading mode gets its own batch, the pass is split before it, its reach is copied (`BlitTexture`) into a pooled backdrop texture, and the shader un-premultiplies, applies the blend function and outputs so normal blending adds the rest. Later draws with the same mode join the batch when they don't overlap its pixels. `PlusLighter` is additive blending in a second pipeline with no copy.
- `CompositeOperator2D` (source-over, copy, source in/out/atop, destination over/in/out/atop, xor, plus lighter, clear) is per-pipeline fixed-function blend state. On draws operators are bounded: the shader discards what a draw doesn't cover, by less than half an 8-bit step, so quad margins don't clear what is beneath. A layer composited with an operator that clears where the source is transparent (`ClearsUncovered`) clears its whole clip.
- A swapchain can't be copied from, so in a frame that blends straight onto one, the target's draws go into a pooled texture and are composited into the window. What was in the window before the frame is not part of the backdrop; a page root is an isolated group anyway. Render-to-texture targets copy directly.

**Shadows** follow Skia's model. `DropShadow2D` (offset, blur radius, colour) is drawing state, applied beneath each fill and stroke as its own instance, usually in the same batch. The blur is Gaussian with standard deviation half the radius, as CSS defines it. Rects, rounded rects and rounded holes blur analytically in the shader (a rect exactly via `erf`, a rounded rect with a banded approximation, a hole subtracting its own blur). Paths, path strokes, glyphs and elliptical-corner rounded rects blur their masks on the CPU (`CoverageBlur`: a separable exact-coverage kernel below a deviation of 8 px, three box blurs above, as SVG sizes them), cached in the mask atlas under the mask key plus the blur. `SetShadowsIgnoreTransforms` puts offset and blur in target pixels (canvas). An inset `box-shadow` is a rect with a hole inside a clip to the box.

**Filter graphs.** `FilterGraph2D` and `FilterRenderer2D` evaluate SVG-style filter graphs on the GPU, one fragment shader per node kind (blend, colour matrix, component transfer, composite, convolve, lighting, displacement, flood, blur, morphology, offset, tile, turbulence, image, colour space conversion) over pooled float textures. They back Booey's accelerated filters.

**Dashing** of a closed contour that starts in a dash holds its first dash back and joins it to the last when that runs round to the start, as Skia's dasher does.

## Krystal.UI

Krystal.UI depends on Booey, Gfx and PAL. `ui::View` (`Krystal.UI/View.hpp`) is the host object for one Booey page, and the unit a host (the editor, a game UI) embeds. It creates the `boo::Page` and main `LocalFrame` with their clients (`ChromeClient`, `FrameLoaderClient`, `DragClient`, `EditorClient`, which the page owns), parses HTML from a string, file or URL (`LoadHTML`, `LoadFile`, `Load`), and owns the viewport, the font face cache, the `TextureMapper`, the image-buffer textures and the overlays. The editor (`Krystal.Editor`) drives a `View` and draws it below its own header.

### A frame

- **Time is passed in, never read.** `View::Update(now, budget)` runs Booey's `EventLoop` with the host's monotonic time: due timers, then queued tasks each followed by a microtask checkpoint, then the rendering update if one is scheduled, then idle callbacks within a budget of at most 50 ms. The engine can pause or scale UI time, and tests drive time without hooks. Call it once a frame, before painting, with a non-decreasing time; it returns whether the rendering update ran. Input methods perform a microtask checkpoint after dispatching. The host passes the window's focus to `View::SetFocused` (a view starts focused); losing it hides an open overlay, confirms the composition and cancels a drag.
- **Paint.** If `NeedsPaint()`, the host calls `View::Paint(Renderer2D&)` between the renderer's `Begin` and `End`. It brings layout and the compositing layers up to date, flushes the layer tree, applies layer animations at the loop's time, paints dirty tiles through `TextureMapper`, composites the layer tree with the frame's renderer (under the renderer's transform when painting began), then paints the overlay and any drag image. The paint path must run after an update that asks for one. `SetDevice` gives the view its device before the first paint; without it the view takes the first device it paints or replays with.
- **Record and replay.** `View::Record()` flattens the page into a `DisplayList` (`PaintBehavior::FlattenCompositingLayers`) and paints as a snapshot, so canvases showing texture pixels paint them into the recording. `View::Replay` replays any display list with the view's fonts.
- **Loading.** `LoadHTML` and `LoadFile` start loads that commit on a later task; the view starts with the frame's initial empty document. `View::DidCommitLoad` paints a committed load (a restored one too) and gives it the view's focus state. A restored page is reported through `DidRestoreFromBackForwardCache` rather than `DispatchDidCommitLoad`, so a host setting up `Document()` on commit sees the right page. `Stop` calls `StopForUserCancel`. Host loads are not asked of the navigation handler.
- **History.** The view owns the page's `BackForwardList` (`GetBackForwardList`, `CanGoBack`, `CanGoForward`, `GoBack`, `GoForward`, `GoToItem`, `Reload`). The mouse back and forward buttons (on release) and Alt+Left/Alt+Right navigate unless the page handled the event. The cache keeps 3 pages unless the host sizes it (`View::DefaultBackForwardCacheCapacity`).
- **Custom elements.** `View::DefineCustomElement(name, factory, options)` applies to each document the view loads, before parsing, and to the current document, upgrading its elements. The view's definitions and focus state go to each document through `DispatchDidClearWindowObject`.

### Display lists, layers and compositing

- Booey paints into display lists and a graphics layer tree. The `ChromeClient`'s graphics layer factory makes `GraphicsLayerTextureMapper`s, which `TextureMapperLayer` composites. The view keeps the painted page in textures and repaints only damage. `TextureMapper::RenderImageBuffer` renders a layer's image-buffer contents ahead of the frame's passes, and `TextureMapper::DrawTexture` draws a texture it doesn't own, with its alpha.
- `ui::GraphicsContextRender2D` is the `boo::GraphicsContext` that replays display lists through Render2D. It is modelled on upstream's Skia backend: mostly one Render2D call per item.
  - It saves the renderer's state on construction and restores it on destruction; resetting the clip brings back the renderer's clip at construction. Each draw first brings the renderer's blend mode, shadows-ignore-transforms and drop shadow up to the context's state.
  - Colours become `Paint2D`s multiplied by the context's alpha; `Gradient` maps field for field to `Gradient2D`; `Path` becomes `Path2D` from its segments. `Render2DConversions` converts colours, rects, transforms, fill rules, caps and joins, rounded rects, paths and gradients; `ToPath2D` follows Skia's path (arcs and ellipses as Render2D's arcs, `arcTo` as canvas draws it, continuous rounded rects as plain ones).
  - Stroke thickness, caps, joins, dashes and miter limit (default 4, as Skia) become `StrokeStyle`; they are kept in a stack beside the context's, as in Skia's backend. Dash arrays that are odd are repeated and invalid ones dropped.
  - Circular rounded-rect corners use Render2D's analytic shapes, including corners within a sixteenth of a pixel of circular (snapping scales radii, which otherwise made 16 px corners 15.99 by 16 ellipses and sent every card through path masks). Elliptical corners are filled, clipped and clipped out as paths.
  - Clip bounds are tracked in target pixels for `ClipBounds`. Clearing a rect uses the clear operator and ignores alpha, shadow and compositing. A rect with a rounded hole and a drop shadow draws only the shadow, 100,000 target pixels away with its offset shifted back (Skia's inset shadow). `drawRect`, `drawLine`, `drawEllipse`, text lines (the spec's decoration rects) and the spelling and grammar underline follow Skia's choices; vertical text is rotated as Skia does.
  - Transparency layers go to `BeginLayer`. The context's style maps to a layer filter (colour matrices as they are; blurs and shadow offsets through the current transform) and the style is cleared for what is drawn inside. A layer with a composite mode composites with its blend mode and draws inside it in source-over, as Skia's does. Compositing operators and luminance-to-alpha map to Render2D's. Clipping to an image buffer's alpha is a Render2D layer that the image masks when the state ends.
  - `DrawControlPart` draws the part on the page's graphics context.
- **Image buffers.** `ImageBufferRender2DBackend` is the accelerated image buffer (canvas bitmaps). It records into a display list; a flush (the rendering update's preparation, or painting) hands what was recorded to be rendered into a texture the buffer keeps, without clearing, the next time the buffer is drawn. Each flushed piece starts with items rebuilding the state the last ended with: state-stack levels with their whole state, transform, line styles and clips, each under the transform it was made in (`ResetClip` is remembered). Readbacks (`GetPixelBuffer`) render there and then and read the texture with `Device::ReadTexture`; copies (`CopyNativeImage`) draw into a new texture, an `ImageBufferSnapshot`.
- `ImageBufferTextures` renders Booey's image buffers (display-list-backed ones once per replay, accelerated ones into the texture they keep) and uploads native images, through renderers of their own that record into the replay's command buffer ahead of its passes. Textures are pooled by size and reused across replays, which is safe because OpenGL runs commands in order. `AcceleratedImageBuffers` (owned by the view) renders outside a paint (`RenderNow`, `Snapshot`) with the view's device, waiting for the GPU before and after because transient memory belongs to the host's frames. Snapshot textures are freed once the commands that may draw them have run (`Retire`, `DestroyRetiredTextures`), and all buffer textures are freed when the view goes.
- **External images.** Every external image Booey draws is a `TextureImage` (a texture on the view's device, drawn without a copy): engine textures (`ui::EngineTexture`: a `gfx::TextureHandle`, size and alpha; shown by a `<canvas>`'s `"krystal-texture"` context through `Compositing/EngineTextureLayer.hpp`) and canvas snapshots.
- **Pattern fills.** A fill or stroke with an image pattern renders the tile image buffer (or uploads its native image) to a texture painted as `ImagePattern2D`: the whole texture is one tile, placed by the pattern space transform, as Skia's shader does.
- **Filters.** `FilterGraph2DBuilder` is Booey's accelerated filter backend. It turns each effect into graph nodes (merges into over composites, drop shadows into their parts, `FEImage` into a source drawn into an image buffer) appended to a `FilterGraph2D`; `GraphicsContextRender2D::DrawFilteredImageBuffer` and `ImageBufferTextures::Filters` apply them with `FilterRenderer2D`.
- **Fonts.** `FontFaceCache` maps a Booey `Font` to a `FontFace2D`, one per FreeType face and synthetic bold or oblique combination, shared by every size. `View::AddFontDirectory` registers font files (`.ttf`, `.otf`, `.ttc`, `.otc`) for every page.
- **Theme.** Controls use upstream's Adwaita theme (`RenderThemeAdwaita`, `ThemeAdwaita`, `ControlFactoryAdwaita`, `themeAdwaita.css`) behind `RenderTheme`'s interface, so another theme can replace it. System colours are semantic, so default black text records its colour in paint dumps. The selection and default focus ring use Adwaita's accent colour.

### Input

`View` takes Krystal.PAL's types (`pal::Key`, `pal::MouseButton`, `pal::KeyModifiers`, `pal::PointerInput`, `pal::CursorShape`) and `Input.hpp` maps them to DOM events (`code`, `key`, legacy key identifier, Windows key code). Everything is routed to the view:
- **Mouse** (`MouseMoved`, `MousePressed`, `MouseReleased`, `MouseLeft`, `MouseWheel`), with click counting and the cursor. A wheel notch is the system's line count (usually 3) times 100/3 pixels; Shift turns the vertical wheel horizontal. Moves carry `movementX`/`movementY` whether or not the pointer is locked.
- **Pen and touch** (`PenInput`, `TouchInput`, `SetPointingDevices`) come from Windows pointer messages (`WM_POINTER*`) through `PointerInput`; press and hold and flicks are turned off, and without the callback the system turns them into mouse input. Touch ids are the lowest free and every event carries all touches on screen. Gestures honour `touch-action`: tap, double tap, pan with fling, long press as `contextmenu`, and pinch-scale of the page between 1 and 5. `SetPointingDevices` drives the pointer and hover media features and `maxTouchPoints` (until set, a mouse alone).
- **Keyboard** (`KeyPressed`, `KeyReleased`, `InsertText`). Tab and Shift+Tab move focus. `EditorClient` runs the editor commands Windows binds keys to (Shift+arrows, Ctrl+A/C and the rest), keeps undo and redo stacks, and applies the input method's composition, which arrives as key presses the input method handled.
- **Gamepads.** The pad mapping lives in Krystal.UI: D-pad and left stick move spatial focus with repeat, A activates, B closes dialogs and popovers (a close request otherwise), bumpers are Tab, and the right stick scrolls. The mapping can be switched off for pages that read pads themselves. `GamepadProvider` wraps the platform layer's XInput pads (polled, dead zones, rumble through `XInputSetState`) in the standard mapping; the host makes it the shared provider and updates it each frame before the view's pad mapping.
- **Pointer lock** is offered to `SetPointerLockHandler`; without one pages can't lock the pointer. Krystal.PAL delivers raw locked-mouse movement.
- **Navigation** by pointer: see History above.

### Text input

Input methods follow GTK's model, the only upstream host whose model fits Krystal.PAL: `SetComposition`, `ConfirmComposition`, `InsertText`, `AcceptsTextInput`, `TextInputRect` (for the host's candidate window) and `SetCompositionDiscardedHandler`. Characters without a key press are typed as a `keypress` carrying them alone, as Windows' `WM_CHAR` is upstream. The page confirms its composition on a mouse, pen or touch press and on window focus loss, and asks the host to drop the input method's.

### Drag and drop

- The host runs the drag. `DragClient` keeps the drag's `SelectionData` and what the source allows. Mouse moves become `DragEnteredOrUpdated`/`DragExited`, release becomes `PerformDragOperation`, then `DragEnded`/`DragSourceEndedAt`. Escape and focus loss cancel, Ctrl copies, and the cursor is OLE's for the operation.
- Krystal.PAL captures the mouse while a button is held, so a drag follows the mouse out of the window and a release there cancels it. The window's OLE drop target is registered only while the host has `OnDrag`; the shell's drop target helper shows the source's drag image over the window.
- Krystal.UI draws the drag image over the page and any overlay at three-quarters opacity: Booey fades selections' and images' images (`DragImageAlpha`) and the host draws the page's own images and links' labels at the same alpha. Links' drag labels follow the old Windows port: a grey rounded rectangle with bold link text over its URL in the system small caption font, each cut to 200 px.
- The editor passes pads, drags (and the answers back to the window), text and composition events to the page view, and gives Escape to a drag rather than quitting.

### Clipboard

The host supplies `PasteboardStrategy` (`typesSafeForDOMToReadAndWrite`, `writeCustomData`, `writeToClipboard`). `SystemPasteboardStrategy` sits over Krystal.PAL's `SetClipboardText`/`GetClipboardText`: it reports the types the clipboard holds, DOM-safe types and custom data by origin, reads files as paths only, and writes a URI list as text when there is no text. Tests and the sample use an in-memory clipboard.

### Overlays

A menu list's popup (`<select>`), the date and time pickers and the colour picker are shown by the host, as upstream asks the chrome client (`PopupMenu`, `DateTimeChooser`, `ColorChooser`); the defaults make none. Krystal.UI implements each as an `Overlay`: an internal `View` placed in the owner's viewport whose generated HTML lists the items.
- `PopupMenuOverlay`: label styles, disabled items, separators, highlight; placed below or above the control within the viewport; scrolls past 20 items.
- `DateTimeChooserOverlay`: a month's calendar, weeks for week inputs, a year's months for month inputs, min and max, arrow and Page Up/Down keys and the wheel.
- `ColorChooserOverlay`: a palette of 40 colours with the input's suggestions first.

While one is open it is painted over the page (and recorded) and takes the keys and mouse: hover highlights, a release chooses, a press outside closes it, and the release of a press that began before it opened goes to the page. It hides before telling its client the choice, as platform menus do. Overlays replace their content's document at once (`ReplaceDocument`). Popups lay out right to left and align to the control's right edge for right-to-left controls; `ColorChooserClient` tells the picker the input's direction (`IsElementRTL`).

### Strategies, providers and host callbacks

- The first `View` installs, unless the host already set one: `FileLoaderStrategy` (the loader; the test loader serves files and text with a type), `SystemPasteboardStrategy` and `PathStrokerStrategy` (Booey's stroke geometry, hit testing and bounds come from Render2D's `PathStroker`, so hit tests match what is drawn).
- The host may set `FileStorageProvider` (local storage, one file per origin in a directory), `GamepadProvider` and the back/forward cache size.
- Callbacks on `View`, all optional with conservative defaults (an action is ignored, alerts show nothing): `SetNavigationHandler` (without one every navigation is allowed, so only same-page navigations happen), `SetLoadHandler` (`LoadEvent`: started, committed, finished, failed), `SetFocusRequestHandler`, `SetCloseRequestHandler`, `SetWindowRectRequestHandler`/`SetWindowRect`, `SetAlertHandler`, `SetConfirmHandler`, `SetPromptHandler`, `SetPrintHandler`, `SetBeforeUnloadHandler`, `SetConsoleMessageHandler`, `SetProtocolHandlerRequestHandler`, `SetPointerLockHandler`, `SetPointingDevices`, `SetUserAgent`. The view also supplies languages, screen and storage.
- The host's dark mode is the main frame's `MediaEnvironment::UseDarkAppearance`, which `Page::UseDarkAppearance()` reads for `prefers-color-scheme`, `color-scheme` and `light-dark()`. `View` has no setter for it, so a host sets it through the frame's `SetMediaEnvironment`.
- The editor sample (`Krystal.Editor`) shows the wiring: the `<bean-rating>` custom element (`BeanRating.hpp`: form-associated, closed shadow root, `:state(rated)`), `PageObservers`, `PageAnimations` and `PagePointers` made once a page has loaded or is restored from the cache, a C++ router for the guide card through a `navigate` listener, back/forward buttons and F5 reload, and a header menu implemented in the page.

## Testing

- **Goldens** are the quality bar for Render2D and Krystal.UI. Scenes (also written as HTML) are rendered offscreen, read back with `ReadTexture`, and compared two ways: with Render2D's own reviewed PNGs (tight tolerance, catching regressions) and with Chrome's rendering of the same HTML (looser tolerance, measuring fidelity). Krystal.Gfx.Tests holds the Render2D scenes (`Scene::ChromeReportOnly` marks report-only Chrome comparisons); page goldens are in `Krystal.UI.Tests/tests/Golden.cpp` and render through `View`. The harness runs the event loop before painting so resources and fonts are loaded. Test devices take a transient memory size because pages draw in many small batches. `KRYS_UPDATE_GOLDENS=1` rewrites goldens; fresh output goes to `build/Krystal.UI.Tests/golden-output`.
- **Chrome comparison policy.** Chrome stands in for WebKit as the fidelity reference, but browsers don't agree pixel for pixel, so comparisons use a per-channel tolerance and a small share of pixels allowed past it; text is only reported. References are captured by `tools/golden/capture_chrome.py` (headless Chrome at device pixel ratio 1; `--golden DIR`). With `tools/golden/cdp.py` it also records `?rects` client rects (`<name>.chrome-rects.txt`), `?record` selection steps (`chrome-editing.txt`) and scripted input actions through the DevTools protocol (`chrome-input.txt`). Headless Chrome lays out at least 500 px wide, so scenes fix their width and put `direction: rtl` on a wrapper, not `<body>`. Chrome draws popups in separate windows, so popup goldens (including `bidi-select-popup`, `bidi-date-picker`, `bidi-color-picker`) are Booey's alone.
- Goldens differ slightly on battery power (the `filters` golden by about 26 pixels); small GPU differences are not regressions.
- A failing golden test tagged `[!shouldfail]` marks a known bug (see Known issues).

## Known issues

### Bugs

- The page-with-a-cached-web-font golden is `[!shouldfail]` (`Golden: a page whose web font is in the memory cache lays out as with a fresh one`): a page whose `@font-face` font comes from the memory cache keeps table cells' preferred widths from before the font applied, so its table is sized differently from a page whose font loads.
- `BlendMode::PlusDarker` is not supported by `Renderer2D`: it asserts in debug builds and draws as `Normal`. `CompositeOperator2D` has no `PlusDarker` or `Difference`, so `GraphicsContextRender2D` falls back to source-over for them (FIXME).
- `MaskAtlas` and `GlyphAtlas` only clear whole pages (the least recently used page the current frame hasn't drawn from), so a page with one mask drawn every frame keeps its stale masks until the atlas is destroyed. Single masks are not freed and pages are not compacted.
- A mask shadow is cached under its fractional position like any mask, so a shadow moving by fractions of a pixel is rasterised and blurred on the CPU every frame.
- Gradients are flattened on every draw, with no cache (513 interpolations per span per draw for a gradient in a non-sRGB space). `StrokePath` also works out the stroke outline on every call, before the mask cache is looked up.
- Each batch that copies the backdrop (a blend mode other than `Normal` or `PlusLighter`) costs a pass split and a copy, and overlapping blended draws copy once each. A draw's reach is a bounding box, so nearby draws may not share a copy.
- A clip chain holds at most 16 shape clips (`Renderer2D::MaxClips`); more assert and the extra clip is dropped. If a frame's transient memory runs out, its draws are dropped (an assert in debug builds).
- Antialiasing is approximate in places. The analytic rounded-box shadow is within about 2 colour steps of numerical integration. Under a transform that stretches unevenly, mask shadows blur by the average scale rather than in the shape's own coordinates. Analytic coverage on curves and diagonals can differ from true area by up to a tenth of a pixel's coverage, and rects thinner than a pixel come out heavier than their true coverage. Flattened gradient colours are within a quarter of a step of the interpolation at the samples and up to half a step at clamping kinks.
- Images cast no drop shadows, and a gradient's shadow uses its shape's coverage as if opaque. Layer `LayerFilter2D::DropShadow` covers CSS `drop-shadow()` filters.
- Buffers of a resolution scale other than 1 replay their transforms unscaled, as the display list was recorded (FIXME in `ImageBufferRender2DBackend.hpp`).
- `EditorClient`'s text-field notifications (`TextFieldDidBeginEditing`, `TextFieldDidEndEditing`, `TextDidChangeInTextField`, `TextWillBeDeletedInTextField`, `TextDidChangeInTextArea`) and `DoTextFieldCommandFromEvent` do nothing.
- Pressing the mouse in the view while an overlay opens does not end the event handler's press (FIXME in `View.cpp`).
- The resizer grip is drawn in pixels rather than the platform's image, and search fields have no recent searches.
- `TextureMapperAnimation.cpp` has two FIXMEs about suspect behaviour: `_totalRunningTime` is cleared where it seems it should not be, and `Pause` is passed a time where it takes a time offset.

### Missing

Render2D and the RHI:
- Elliptical corners: `RoundedRect2D`/`CornerRadii2D` and the analytic rounded hole are circular per corner. Elliptical corners (`border-radius: 10px / 20px`, percentage radii on non-square boxes, inner border edges of unequal sides) are drawn by the caller as paths through coverage masks.
- Blurs read only what is inside the clip, so damage inside blurred layers grows to everything painted, and blur reaches up to 256 px. Blur edge modes are `None` and `Duplicate` only.
- Coverage-correct antialiased edges for unbounded operators on draws.
- Text contrast and gamma adjustment (Skia's) and DirectWrite-like rendering.
- No partial clear in Render2D (the page clears by drawing into a second texture and copying). No threaded painting or compositing.
- Colour management: sRGB only. The colour space passed to a host image buffer is ignored, and the view's target and the page's pixel readback are sRGB, 8 bits a channel (FIXME in `View.cpp`).
- `Path` has no platform implementation: arcs are flattened into bezier curves, and the platform path used where a segment can't produce elements or be transformed isn't available (FIXME in `Graphics/Path.hpp`).
- No hardware blending through `KHR_blend_equation_advanced`.
- Render2D is 2D only: no perspective or 3D rendering contexts, so `TextureMapperLayer` flattens 3D transforms (FIXMEs). Replicas (reflections), reference filters in `TextureMapper`, masks and backdrops on `TextureMapperLayer`, contents scaling filters (`image-rendering` on composited images and canvases) and repeating textures are FIXMEs too.
- RHI: no compute, texture views, explicit barriers (OpenGL doesn't need them; another backend would), multiple queues, multithreaded command recording, bindless resources or push constants. There is no second backend (Vulkan or D3D) and no shader toolchain (reflection, offline compile, SPIR-V, cross-compilation); the OpenGL context is WGL only and `gl.cpp` has a Windows-only loader (FIXME). There is no 3D scene renderer (cameras, lights, meshes). Krystal.UI loads fonts and images directly; there is no shared asset layer.

Krystal.UI and the host:
- Host-reported system values are constants: the double-click time (500 ms) and distance (2 px) and the touch thresholds (double-tap distance, pan threshold, long-press time) on `View` (FIXMEs); the system's caret blink, reduced-motion and contrast settings; the page's screen position (`screenX`/`screenY` on mouse, touch and pen events, unless the host calls `SetWindowRect`; FIXMEs in `Input.cpp` and `View.cpp`); dead keys (`"Dead"`), which the platform layer doesn't report.
- Input methods: a host `CompleteComposition()` on the window is unused, and there is no input purpose or hints.
- Drags from other applications: the host reads a drag's data once as it enters. The legacy `FileName`/`FileNameW` formats, virtual file descriptors (browser-dragged images and links), pages' custom data and smart pasting are not read. Drags out of a page to other applications are not supported. A drag carrying files is never offered a move. Krystal.PAL's OLE side is not driven by tests.
- No host-supplied file picker for `<input type=file>`, and no autofill (FIXME in `EditorClient.hpp`).
- `FileStorageProvider` writes local storage on every change, on the main thread, and `FileLoaderStrategy` reads files on the main thread (FIXMEs).
- The date and time chooser uses fixed English names and first day of the week (FIXME for the locale's); colour inputs' `alpha` and `colorspace` and user activation for pickers are not handled. Typing to choose in an open popup is not supported, and the popup's own scrollbar look differs.
- Controls: devolvable widgets (FIXMEs in `RenderTheme.cpp`), checkmarks for `appearance: base`, customizable `<select>` (`appearance: base-select` parses but draws as `auto`), file inputs, datalists and tick marks, the validation message bubble, media controls, Apple Pay and attachment parts, and search-field icons.

## Differences

### From the specs

- Render2D blends sRGB-encoded values everywhere, as browsers do, rather than in linear light. Layer textures use the target's format (8-bit unorm, as browsers do) rather than 16-bit float.
- Coverage is sampled in 16 sub-scanlines per pixel row (exact horizontally, sixteenths vertically), like Chrome's CPU scan converter, and curve flattening stays under a fiftieth of a pixel of error. Exact-area accumulation was rejected because it can't do even-odd.
- Date and time fields: partly filled dates report bad input.
- The date inputs' locale comes from `lang` when `Settings::LangAttributeAwareFormControlUIEnabled` is on, else the user interface's; `Locale`/`LocaleICU` use ICU.

### From WebKit

- Booey's painters are upstream's, but they draw through Render2D, whose rendering model is its own: a GPU instance batcher with analytic shapes and CPU coverage masks, not Skia or Core Graphics. Differences in antialiasing and shadow blurs follow from that.
- Text is read from the clipboard as `CF_UNICODETEXT` else `CF_TEXT` in the system code page (upstream read Latin-1); markup is Firefox's `text/html` else the HTML format's fragment.
- The host answers a drag a frame late: the source hears the host's answer at its next move and at the drop, as WebKit2's UI process uses the last operation. Entering answers no operation. A release where the last answer was no operation comes as a leave, not a drop. Over the editor's header, or with another view shown, a drag is off the page. Drag positions are not offset by the drag offset. `setDragImage()` after the drag started does not change the image.
- Input methods are driven GTK-style rather than as Windows' WebKit port does.
- The control theme is Adwaita (a GTK look), not a native Windows one.
- Week inputs have a week field (Chrome's layout, beyond upstream); date inputs focus through the HTML focus model (the user agent shadow root delegates focus), so fields are focused, clicked and tabbed between and a disabled input's fields are not focusable.
- Layers are composited on the main thread through `TextureMapperLayer`; upstream's coordinated graphics commit layers at flush into a scene a compositor thread owns (`ThreadedCompositor`, async scrolling). That is worth doing only once something can keep the main thread busy.
- There is no scripting, so handlers are C++ functions: no string handlers, no `setTimeout` extra arguments (lambda captures stand in), no realms.

### From Chrome

- Backdrop blur edges are duplicated rather than mirrored, so goldens differ along the glass's edges.
- Text-control and number-field layouts differ slightly from Chrome's (report-only goldens).
- The control theme is Adwaita rather than Chrome's. Popups are drawn by the page's own overlays; Chrome's are separate windows. Matching Chrome is the long-term aim, with the theme staying behind `RenderTheme`'s interface so a Chrome-like theme (Blink's `LayoutThemeDefault` and `NativeThemeBase`) can replace it.
