# Krystal.Booey

Booey is the engine's web engine: the DOM, HTML and CSS for declaring, changing and rendering documents in C++ applications. Read `docs/OVERVIEW.md` (scope, conventions, the build) before working on it, and the sections of `docs/ARCHITECTURE.md` for the areas the task touches.

## Documents

- `docs/OVERVIEW.md`: scope, conventions and the build.
- `docs/ARCHITECTURE.md`: how each area (DOM, CSS, layout, painting and so on) is put together.
- `docs/DIFFERENCES.md`: where Booey differs from the specs and Chrome, by area.
- `docs/KNOWN-ISSUES.md`: known bugs and missing features, by area.
- `docs/WEBKIT-PROVENANCE.md`: the WebKit file each ported file came from and its licence (LGPL ones listed first). A newly ported file starts with its source's copyright notice, verbatim, and gets a row there.
- `docs/specs/`: review checklists of the specifications' algorithms, by section (`DOM.md`, `INFRA.md`, CSS modules in `css/`, and HTML one per page of its multipage edition in `html/`, indexed by `HTML.md`), generated by `tools/spec_checklist.py`.
- `tools/spec_status.py`: each checklist's progress (HTML's by page: `html <page>`), and where each algorithm is linked from the code and tested.

## Working on Booey

- **Keep the documents current:** a new or changed difference from the specs or Chrome goes in `DIFFERENCES.md`; a bug found but not fixed gets a `[!shouldfail]` test with a FIXME and an entry in `KNOWN-ISSUES.md`; a fix removes its entry.
- **Scope:** keep standard features a C++ application could use, even before Booey does; remove browser-oriented ones (the not-planned list in `docs/OVERVIEW.md`), `-webkit-`/`-apple-` and non-standard features.
- **Reviewing against a specification:** work through a checklist a section at a time (`python Krystal.Booey/tools/spec_status.py dom <section anchor>` lists each algorithm's code and tests).
  - Label each step in its implementation as `// 1.`, `// 1a.`, `// 1a.i.` followed by the step's text, as the checklist numbers them. A step left out on purpose is `// 3. (Skipped: <reason>.)` with a `DIFFERENCES.md` entry; a missing or wrong one is a bug as above. Single-sentence algorithms and definitions need no labels.
  - Tag the tests that cover an algorithm with `[<spec>:<anchor>]` (`[dom:concept-node-pre-insert]`). Existing tests for it move into the test file matching the file that implements it (pre-insert's into `tests/DOM/Algorithms/MutationAlgorithms.cpp`), named after the algorithm and behaviour.
  - Sections without algorithms (such as Trees) still get reviewed: check their definitions against the code, note where they live in `>` lines under the status, and tag their tests with the definition's or section's anchor.
  - Tick it and set the section's status with `python Krystal.Booey/tools/spec_status.py <spec> --tick <section anchor> --note "..."`.

## Gotchas

- Every header and source is listed in `CMakeLists.txt`; a file that isn't listed isn't built. After a trial compile (temporarily adding a file), re-run `cmake --preset windows-x64` once it's reverted, or the generated project keeps the file.
- Booey is a unity build: file-local helpers share a batch, so make them unique or shared, and include what each file uses (see *The build* in `docs/OVERVIEW.md`).
- Tests that create `Value`s need the static value pool: use `ValueFixture` from `Krystal.Booey.Tests/CSS/ValueTestUtils.hpp` (it also has `CssText`, `ToNarrow` and `Children`).
- Catch2 can't print `std::u8string` (shows `{?}`); to see a failing string, print it from a temporary test.
- Inside `css::calc`, `Number`/`Percentage` are calc nodes; the primitives are `css::Number<...>`.
